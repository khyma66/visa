## Implemented in the app

The October 2 consolidation adds separate login and signup screens. Signup verifies email with a one-time code, then offers password setup. Login supports password or an email code. Password setup verifies the user against the auth server and requires a confirmed email and 12–128 characters. Codes and passwords are held only in component state; Supabase validates them. Resend has a 60-second UI cooldown in addition to backend limits. Errors do not expose raw provider responses. Existing identity-scoped UI resets and database policies are preserved.

Google checks the project's public auth settings and stays disabled when the provider is disabled. Apple is removed, following the latest decision in “Check Latest Status Changes”. Enabling Google makes its button usable after page reload; no rebuild is required. OAuth uses PKCE. The browser SDK automatically exchanges the callback code before its initial session result. Do not add a second exchange handler. The callback is `/login?auth=callback&next=...`; destinations are restricted to local paths.

October 4 typography/sign-in update: Google and Phone are now visible on both login and signup, with an explicit “Not available yet” label and disabled controls until each provider is enabled. Loading/error states fail closed, while email remains selectable. Dashboard inspection confirmed Google is off with empty client fields; Phone is off with empty Twilio account, token and messaging-service fields. No provider was enabled and no SMS was sent. Login code requests explicitly use `shouldCreateUser: false`; signup uses `true` only after its policy acknowledgement. Phone-only users skip email-password setup. Client-side checks do not replace backend policy enforcement or abuse controls.

To finish Google, identify the owner-approved VisaThreads Google Cloud project, configure branding and a Web OAuth client with origin `https://visathreads.com` and the callback below, enter its secret directly in the dashboard, then complete real-account/cancel/retry testing. For phone, choose an SMS provider and approved sending countries, confirm messaging costs and sender-registration requirements, configure credentials directly in the dashboard, and implement CAPTCHA/rate limits before enabling it. Obtain an authorized test number before sending a code. See [phone login requirements](https://supabase.com/docs/guides/auth/phone-login). These steps and email delivery verification remain outstanding.

The shared typography follows [Stack Overflow Stacks](https://stackoverflow.design/system/foundation/typography): its system font stack, 14px body, 13px captions, 600 bold, 28px desktop main headings and 23px mobile main headings (at the standard 16px browser root). Responsive sizes use `rem`; mobile form inputs retain 16px to avoid focus zoom. VisaThreads branding and layout remain independent.

## Acceptance checks

- Existing account: request code, enter correct code, return to the originating page; reload retains session.
- New account: request code, verify, generated public username exists and real name/email is not published.
- Wrong/expired/reused code: helpful error, no session, resend works after cooldown.
- Google: approved test account completes sign-in on the same browser; cancel stays branded and retryable. Check existing-email account linking.
- Signup: verify code, set password, sign out, and log in with that password. Recovery must work without exposing whether an email exists.
- Sign-out and account switch clear prior private conversations. Email-code login remains available.
- The owner approved a sign-in test inbox on October 4. The first send attempt was rejected before delivery because Resend domain verification was pending. Retry once verification succeeds; do not assume delivery or send additional categories of test email without authorization.

## Controls confirmed by this review

- New community message/conversation SELECT policies check membership. Anonymous direct-message reads are not granted.
- Direct INSERT into new messages and UPDATE of message bodies are not granted to members; guarded RPCs are used. Only the recipient read-marker column is updatable under its policy.
- Members cannot directly change question status; anonymous moderation execution is denied. Report reads are limited to the reporter. Moderator allowlist is private, not user-editable profile metadata.
- Public `profiles` columns are id, username, avatar seed, bio, reputation and timestamps; no login email field. This does not establish that old tables are safe.
- Private moderator/rate-window/suspension tables intentionally have RLS without browser policies. That is deny-by-default, not a defect needing permissive policies.
- Current UI renders question/answer/message bodies as React text. Import source URLs are restricted to HTTPS by normalization, but HTTPS alone does not establish a trustworthy destination.
- Production launch and import gates remain false. Browser-safe Supabase key configuration is checked; public server rendering does not forward a private session. Cache/framing/referrer headers are tested, subject to real-host verification.

## Operational hardening still required

Require MFA and least-privilege membership for Cloudflare, Supabase, GitHub, domain registrar and email provider; store recovery codes safely. Protect production approvals/branches, restrict CI secrets to trusted jobs, pin reviewed third-party Actions to immutable revisions, and do not run untrusted fork code with production secrets. Keep dependency/security alerts enabled and assign patch ownership.

Define alert thresholds for availability, database saturation, signup/email failures, unusual direct-API writes, message/report spikes, and spending. Limit logs to necessary metadata; avoid message bodies, login tokens and identity documents. Document log access and retention. Back up database **and separately any storage objects**, test restore in an isolated target, and agree recovery time/data-loss objectives. Database network restrictions do not replace RLS on the public Data API.

Incident drill: preserve relevant audit evidence without broadly copying personal data, contain the affected access path, revoke compromised credentials/sessions, involve the named security lead and counsel, assess applicable notifications, restore safely, and record lessons. Do not promise a universal breach-notification deadline; requirements vary by jurisdiction and facts.
